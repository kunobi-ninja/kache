---
title: Kache
description: A local-first compiler cache for Rust, C/C++ and CUDA builds
---

Kache stores compiler outputs by content and reuses them across builds, repositories, and worktrees. The local cache works on its own. S3-compatible and filesystem remotes are optional.

## Get started

Install Kache:

```bash
cargo install kache
```

Then enable it:

```bash
kache init
```

Keep running `cargo build` as usual; Kache now caches the compiler outputs.

`kache init` sets Cargo's `rustc-wrapper` and installs a login service for the background cache. It asks before each change and backs up files it edits.

[Other install methods](/docs/getting-started/installation) include Homebrew, APT, winget, and Nix. The [quick start](/docs/getting-started/quick-start) shows how to confirm cache hits. For a comparison with sccache, read [Kache or sccache?](/docs/getting-started/comparison).

## Current support

| Area | Support |
| --- | --- |
| Rust libraries and build scripts | Linux, macOS, and Windows. Build-script runs are cached on Linux and macOS |
| Rust executables | Enabled by default on Linux and macOS; disabled by default on Windows |
| C and C++ object compilation | GCC, Clang, Apple Clang, and clang-cl. MSVC `cl.exe` is not cached |
| CUDA object compilation | Single-source `nvcc -c` and `-dc` |
| Local cache | Content-addressed storage with automatic garbage collection |
| Remote cache | S3-compatible and filesystem backends |
| Build visibility | Live monitor, stats, miss explanations, and reports |

Kache passes unsupported compiler invocations through unchanged. A passthrough is not a cache hit or miss; inspect its reason in the monitor's Why tab or debug logs.

## Tested nightly on real projects

The [nightly benchmark workflow](https://github.com/kunobi-ninja/kache/actions/workflows/bench.yml) runs cold/warm builds of Firefox, LLVM, SurrealDB, Lance, OpenDAL, cuda-oxide, and eza on Linux. Separate workflows build Firefox on Windows every night and compare Firefox with sccache once a week. Reports, traces, and logs are retained for 30 days.

Benchmark numbers count only when the individual job succeeds and its self-checking verdict is `ok`.
