Kache ships two executables: the `kache` client and `kache-engine`. Keep the same
version of both in the same directory when installing a release manually.

```bash
cargo install kache --locked --version 2.0.0-rc.3
kache init
```

`kache init` configures Cargo to use Kache. Your Cargo commands stay the same.

## Release channels

These docs track v2 on `main`. The command above pins the published v2 preview.
The package-manager commands below without a prerelease version select the stable
channel and do not opt into v2 release candidates.

For a reproducible preview installation, request `2.0.0-rc.3` explicitly with
Cargo, cargo-binstall, or mise. Homebrew and Windows also have separate unstable
packages; APT has an unstable distribution. Check the
[release list](https://github.com/kunobi-ninja/kache/releases) before selecting a
newer version.

Optional Blaze routing is available from `v2.0.0-rc.3`.
The [upgrade guide](/docs/getting-started/upgrade-v2) covers
existing installs and what state can start cold.

## Package managers

<Tabs items={["Homebrew", "APT", "Windows", "AUR", "mise"]}>
  <Tab value="Homebrew">
    ```bash
    brew install kunobi-ninja/kunobi/kache
    ```

    Use `kunobi-ninja/kunobi/kache-unstable` for release candidates and betas.
  </Tab>
  <Tab value="APT">
    ```bash
    sudo mkdir -p /etc/apt/keyrings
    curl -fsSL https://r2.kunobi.com/kache/apt/gpg.key \
      | sudo gpg --dearmor -o /etc/apt/keyrings/kache.gpg
    echo "deb [signed-by=/etc/apt/keyrings/kache.gpg] https://r2.kunobi.com/kache/apt stable main" \
      | sudo tee /etc/apt/sources.list.d/kache.list
    sudo apt update
    sudo apt install kache
    ```

    Replace `stable` with `unstable` to receive prereleases as well as stable releases.

    The package also installs Cargo and compiler shims in `/usr/lib/kache`. Prepend that directory to `PATH` to cache Make and CMake object compiles. See [C and C++](/docs/getting-started/c-cpp).
  </Tab>
  <Tab value="Windows">
    ```powershell
    winget install kunobi-ninja.kache
    # or
    scoop bucket add kunobi https://github.com/kunobi-ninja/scoop-kunobi
    scoop install kunobi/kache
    # or
    choco install kache
    ```

    The corresponding prerelease packages are `kunobi-ninja.kache.Unstable`, `kunobi/kache-unstable`, and `choco install kache --pre`.
  </Tab>
  <Tab value="AUR">
    ```bash
    paru -S kache-bin
    ```

    `kache-bin` is the official prebuilt package. `kache-git` builds the current main branch; the community `kache` package builds a release from source.

    Both official packages install Cargo and compiler shims in `/usr/lib/kache`. For `makepkg`, put `PATH="/usr/lib/kache:$PATH"` in `~/.makepkg.conf`.
  </Tab>
  <Tab value="mise">
    ```bash
    mise use -g github:kunobi-ninja/kache@latest
    ```

    Release candidates do not resolve as `latest`. Request their full `x.y.z-rc.n` version explicitly.
  </Tab>
</Tabs>

## Nix

### nixpkgs

Kache is available in nixpkgs-unstable. Install its package with:

```bash
nix profile install github:NixOS/nixpkgs/nixpkgs-unstable#kache
```

On NixOS, add `pkgs.kache` to `environment.systemPackages` and set `RUSTC_WRAPPER` to `"${pkgs.kache}/bin/kache"`. The separate `pkgs.kache.shims` output provides C/C++ wrappers in `${pkgs.kache.shims}/bin`; put that directory before the real compilers on `PATH` to cache native compilations.

### Kache flake

Use Kache's flake to follow its releases directly or use its NixOS and nix-darwin modules.

The flake builds for x86_64-linux, aarch64-linux and aarch64-darwin. On Intel macOS, use Homebrew, a release binary or `cargo install`.

The `stable` branch follows released versions:

```bash
nix run github:kunobi-ninja/kache/stable -- --version
nix profile install github:kunobi-ninja/kache/stable
```

Pin a release tag when updates must be explicit:

```bash
nix profile install github:kunobi-ninja/kache/v2.0.0-rc.3
```

The flake also exports `overlays.default`, `nixosModules.default` and `darwinModules.default`. The module's `services.kache` options are defined in [`packaging/nix/module.nix`](https://github.com/kunobi-ninja/kache/blob/main/packaging/nix/module.nix). `enable` installs Kache, writes `settings` to `/etc/kache/config.toml` and sets `KACHE_CONFIG`. `rustcWrapper`, on by default, sets `RUSTC_WRAPPER`. `daemon.enable` runs the daemon as a systemd or launchd user service. The module does not put the shims on `PATH`; use the example below for that.

The package includes `cargo`, `cc`, `c++`, `gcc`, `g++`, `clang`, `clang++`, and `rustdoc` symlinks in `${kache}/shims`. With this flake's `overlays.default` applied, enable them in your NixOS configuration:

```nix
{ pkgs, ... }:
{
  environment.systemPackages = [ pkgs.kache ];
  environment.sessionVariables = {
    RUSTC_WRAPPER = "${pkgs.kache}/bin/kache";
    PATH = [ "${pkgs.kache}/shims" ];
  };
}
```

Keep the real compilers later in `PATH`. The compiler shims cover C and C++; Rust still uses `RUSTC_WRAPPER`. Point `build.rustdoc` at the `rustdoc` link for the [supported rustdoc mode](/docs/getting-started/rustdoc). Plain `cargo doc` passes through. The Cargo shim protects targets while Cargo commands run. Nix builds the symlinks, so no `kache init --shims` step is needed. The existing `${kache}/lib/kache` path remains available.

## Supported release targets

| Platform | Architectures |
| --- | --- |
| Linux, musl | x86_64, aarch64 |
| macOS | x86_64, Apple silicon |
| Windows, MSVC | x86_64, ARM64 |

Other Rust-supported targets may work through `cargo install`, but they are not release-tested targets.

## Shell completions

`kache init` installs completions for your login shell on Unix: Bash, Zsh, or Fish. Open a new terminal after setup. Run `kache init` again after an upgrade to refresh the scripts; `--check` previews changes and `--no-shell` skips them.

Bash and Zsh load a generated script from `${XDG_DATA_HOME:-~/.local/share}/kache/completions`. Fish uses `${XDG_CONFIG_HOME:-~/.config}/fish/completions/kache.fish`. Existing files are backed up before replacement.

The official AUR packages also install completions for Elvish. For manual setup or another supported shell, use [`kache completions <shell>`](/docs/commands/reference#kache-completions).

## Upgrading from 1.x

Follow [Upgrading to v2](/docs/getting-started/upgrade-v2). Finish active builds,
install the matching pair, keep the existing configuration, and restart the
daemon. Custom installers and container images must include `kache-engine`.

## Verify the install

```bash
kache --version
kache doctor
kache doctor --probe
```

If you have not run it yet, enable Kache with `kache init`. The [quick start](/docs/getting-started/quick-start) shows how to confirm cache hits.

## Build from source

To install the current main branch, including features not yet in a release:

```bash
cargo install --git https://github.com/kunobi-ninja/kache --branch main --locked kache
```

Or build from a checkout:

```bash
git clone https://github.com/kunobi-ninja/kache
cd kache
cargo install --path . --locked
```

A git checkout builds with the toolchain pinned in `rust-toolchain.toml`, which rustup installs on first use.

Both commands install `kache` and `kache-engine`. Build locally without installing
with `cargo build --release --bins`; keep the two outputs together if you copy
them from `target/release/`.
