<Callout type="warn">
The planner service and Helm chart are previews. Deployment, authentication, and HA behavior may still change.
</Callout>

The planner ranks likely artifacts before rustc asks for exact keys. It is optional: local caching, exact remote lookup, sync, and client-side fallback planning work without it.

## API and state

The service in [`crates/kache-service`](https://github.com/kunobi-ninja/kache/tree/main/crates/kache-service) exposes:

- `POST /v1/prefetch-plan`
- `GET /healthz`
- `GET /readyz`
- `GET /.well-known/kunobi-auth` (only with [Kunobi login](#authentication) enabled)

The client rewrites an endpoint configured with the older `/v2/prefetch-plan` path to `/v1`. When no useful candidates exist, the service returns a fallback disposition and the client uses its normal planner.

Planner state is stored in an embedded SQLite database, at the path given by `--db-path` / `KACHE_PLANNER_DB_PATH`. `kache save-manifest` writes manifests to the configured remote; it does not post them directly to this service. Current deployments seed or ingest that data separately.

## Run locally

```bash
cargo run -p kache-service
```

The default bind address is `0.0.0.0:8080` and the default database path is `/var/lib/kache/planner.db`. Override them with `--bind` / `KACHE_PLANNER_BIND` and `--db-path` / `KACHE_PLANNER_DB_PATH`.

See [Authentication](#authentication) to require a bearer.

## Authentication

With no provider configured, the planner accepts anonymous requests. Configure any of these and `POST /v1/prefetch-plan` requires a bearer that one of them accepts. The health, metrics and discovery endpoints stay open.

| Provider | Service flags (env) | Clients |
|---|---|---|
| Static token | `--token` (`KACHE_PLANNER_TOKEN`) | set `KACHE_PLANNER_TOKEN` |
| Kunobi login (OIDC) | `--oidc-issuer` (`KACHE_PLANNER_OIDC_ISSUER`), `--oidc-client-id` (`KACHE_PLANNER_OIDC_CLIENT_ID`) | run `kache login` once |
| GitHub Actions OIDC | `--github-oidc-audience` (`KACHE_PLANNER_GITHUB_AUDIENCE`), `--github-owner` (`KACHE_PLANNER_GITHUB_OWNERS`, comma list) | job has `permissions: id-token: write` |

**Kunobi login.** Register a public OAuth client (PKCE, no secret) with redirect URI `http://localhost:8329/callback` and scopes `openid profile email offline_access`; enable the device grant for `kache login --device`. The client id is the accepted token audience. The service advertises the issuer and client id at `/.well-known/kunobi-auth`, which is how `kache login` finds them.

**GitHub Actions.** Tokens must carry the configured audience, and their `repository_owner` claim must match one of the `--github-owner` values (case-insensitive). The service refuses to start with an audience but no owner, since that would trust every repository on GitHub. The kache client fetches the job's token itself when `ACTIONS_ID_TOKEN_REQUEST_URL` is present; its audience is `KACHE_PLANNER_GITHUB_AUDIENCE` / `cache.planner.github_audience` (default `kache`).

A client that cannot authenticate plans locally, exactly as when the planner is unreachable.

## Helm

```bash
helm upgrade --install kache-service ./packaging/charts/kache-service
```

The chart supplies a Deployment, Service, probes, optional persistent volume, optional authentication (existing-secret token, Kunobi login, GitHub Actions OIDC), optional Lease-based leader election, and an optional Ingress.

```yaml title="values.yaml"
auth:
  oidc:
    issuer: https://clerk.kunobi.com
    clientId: <public client id>
  githubOidc:
    audience: kache
    owners: [my-org]
```

Point clients at it:

```bash
export KACHE_PLANNER_ENDPOINT=http://kache-service.namespace.svc.cluster.local:8080
export KACHE_PLANNER_TOKEN=secret-if-required
```

To reach it from outside the cluster, enable the Ingress:

```yaml title="values.yaml"
ingress:
  enabled: true
  className: nginx
  host: kache.example.com
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt
  tls:
    enabled: true
```

The Ingress does not add authentication. Configure [a provider](#authentication) before you expose the service beyond a trusted network.

The equivalent TOML is under `[cache.planner]`.

## Persistence and HA

The chart defaults to ephemeral `emptyDir` planner storage. Choose `pvc` when state must survive pod replacement:

```yaml title="values.yaml"
planner:
  persistence:
    enabled: true
    type: pvc
    size: 10Gi
```

Enable leader election for multiple replicas:

```yaml title="values.yaml"
replicaCount: 2
ha:
  enabled: true
  leaseName: kache-service
```

Followers remain live but not ready. If replicas share one embedded database, the volume must support their mount pattern; otherwise keep one replica.
